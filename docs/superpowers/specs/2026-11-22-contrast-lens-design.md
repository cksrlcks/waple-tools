# 명도대비 렌즈 (`a11y.contrast_lens`) 설계

작성일: 2026-11-22 · 기준 문서: [docs/plan.md](../../plan.md), [2026-11-20-cvd-lens-design.md](2026-11-20-cvd-lens-design.md)

## 1. 왜

색맹 안경처럼 화면 위에 떠 있는 프레임을 대면, 그 안의 글자가 WCAG 명도대비 기준을 넘는지 보여 준다.
DOM이 없는 화면(디자인 시안, 다른 앱, 이미지)도 검사할 수 있게 화면 픽셀로 판단한다.

## 2. 목표 / 비목표 / 실패 조건

**목표**

- 접근성 탭의 **추가 설치 도구(DLL)** "명도대비 렌즈", AI 뱃지.
  - 처음엔 AI 없이 픽셀만으로 만들었다(1차). 수동 확인 뒤 사용자 결정(2026-11-22)으로 글자 영역은 **PaddleOCR PP-OCRv5 mobile det**으로 찾는다.
    실시간이 아니라 **클릭할 때 검사**한다 (사용자: "완전 실시간으로는 하지 말고 클릭하면 그 부분을 스크린샷해서 점검").
- 글자 기준 두 개, 하나만 또는 둘 다 고른다 (사용자 결정). **렌즈 손잡이의 토글에서만** 고른다(앱 화면에는 기준 옵션이 없다, 사용자 결정 2026-11-22). 렌즈는 둘 다 켠 채로 뜬다.
  - `4.5:1` 본문 글자 (WCAG 1.4.3)
  - `3:1` 큰 글자 · 아이콘 · UI 요소 (WCAG 1.4.3 큰 글자, 1.4.11)
- [렌즈 띄우기] 실행 버튼 → 떠 있는 렌즈. 렌즈 안 글자 줄·아이콘마다 상자와 대비값: 통과는 초록(`11.7:1`), 미달은 빨강.
  미달 상자 글은 `3.9:1 미달`처럼 대비값만 (어느 기준까지 충족하는지는 쓰지 않는다, 사용자 결정 2026-11-22).
  (1차는 미달만 그렸으나 수동 확인에서 "글자 인식이 전혀 안 된다"로 보여 통과도 그린다)
- 렌즈 안쪽은 클릭·스크롤이 아래 화면으로 통과한다.
- 아이콘(작고 색이 한두 가지)도 3:1로 검사한다. 그림은 뺀다.

**비목표**

- 글자 크기로 기준 자동 선택 (det 상자 높이로 가능하지만 사용자가 고른 기준을 쓴다. 필요하면 다음에)
- 글자 읽기(rec), 실시간 검사, 스포이트, 결과 저장, 색맹 안경과 합치기
- 사진·그라데이션 배경 위 글자의 정확한 판단 (배경을 한 색으로 정할 수 없는 상자는 건너뛴다)

**실패 조건**

- 렌즈 자신(테두리·상자)이 캡처에 찍혀 다시 분석된다
- 안티에일리어싱 가장자리·회색 가는 획 때문에 통과 글자가 미달로 뜬다
- 도구를 열기만 했는데 렌즈가 뜬다, 렌즈가 떠 있는 동안 제거·업데이트하면 앱이 죽는다
- 모델을 실행 중에 받는다, 네트워크, 이 도구 전용 앱 화면 코드

## 3. 방식 (고려한 것)

글자 영역:

| 방식 | 장단점 | 결정 |
|------|--------|------|
| 픽셀만: 칸마다 배경색 + 다른 색 픽셀 덩어리 | AI 없음, 아이콘도 잡힘. 글자인지 모름, 그림·로고까지 잡힘 | 1차. 이후 아이콘 찾기로만 쓰다가 뺐다 |
| PP-OCRv5 **mobile** det (4.8MB) | 글자 줄 정확. 렌즈 크기 화면 약 0.08초(첫 실행 0.12초, CPU). 아이콘 못 잡음 | **채택** (사용자) |
| PP-OCRv5 server det (88MB, 대체텍스트와 같은 모델) | mobile과 상자가 거의 같고 약 0.66초 | 뺌 |

2026-11-22 같은 화면(840×570, 글자 12줄) 측정: server 12상자 / mobile 13상자(`■` 하나 더), 위치 거의 같음.

캡처·표시:

| 방식 | 결정 |
|------|------|
| 레이어드 창(픽셀 알파) + `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` + 화면 DC `BitBlt` | **채택**. 시험으로 레이어드 창도 BitBlt 캡처에서 빠짐 확인 (대조: 플래그 없으면 찍힘) |
| Magnification API (색맹 안경 방식) | 픽셀 값을 읽을 수 없어 뺌 |

## 4. 설계

### 4.1 카탈로그 · 크레이트 · 옵션 · 모델

- `catalog/tools.json`: `a11y.contrast_lens` "명도대비 렌즈", `"builtin": false, "ai": true`.
- CLAUDE.md·plan.md 작업 규칙의 AI 허용 목록에 `a11y.contrast_lens` PaddleOCR PP-OCRv5 mobile det(글자 영역만, 2026-11-22)를 더한다.
- 모델: `PaddlePaddle/PP-OCRv5_mobile_det_onnx`의 `inference.onnx` (Apache-2.0, PaddlePaddle 공식 ONNX). `scripts/fetch-models.sh a11y.contrast_lens`로 `crates/tools/a11y-contrast-lens/model/det.onnx`에 받고(sha256 확인, git 제외) `include_bytes!`로 DLL에 넣는다. `build.rs`: 모델이 있으면 `has_model`, addon 빌드인데 없으면 멈춤, DirectML 등 지연 로드(다른 AI 도구와 같음). 모델 없이 빌드된 판은 [렌즈 띄우기]에서 "이 빌드에는 AI 모델이 들어 있지 않습니다." 오류.
- `addon-release.yml`: 모델 받기·AI 고지 올리기 조건에 이 도구를 더한다. `ai-common/NOTICE.txt`에 mobile det 출처를 더한다.
- 검출 전처리·후처리는 대체텍스트와 같다(두 모델의 `inference.yml` 기본값이 같음): `ai-common`의 `det` 모듈(`detect`, `det_size`, `det_boxes`)로 옮겨 두 도구가 같이 쓴다. 대체텍스트 동작은 그대로.
- 크레이트 `crates/tools/a11y-contrast-lens/`, `export_tool!`, `ToolKind::Interactive`, 루트 `x-input: "none"`.
- 옵션: `action`(enum 값 하나 `show` "렌즈 띄우기", `x-run-buttons`) 하나뿐. 작업대는 버튼이 하나면 폭 전체로 크게 그린다(공용).
- `run()`: 렌즈가 없으면 띄우고, 있으면 다시 검사하고 앞으로 가져온다 (색맹 안경 5.2·5.3·5.3.1과 같은 수명·하나만 규칙, 창 클래스 `WapleContrastLens`).

### 4.2 분석 (`analyze.rs`, 순수 함수 · `ocr.rs`)

입력: BGRA 캡처, 폭·높이, 고른 기준, det 글자 줄 상자.

1. 대비: WCAG 상대휘도(sRGB 선형화) `(L1+0.05)/(L2+0.05)`.
2. **글자** (det 상자마다, 이미지 안으로 자름): **상자 가장자리 띠**(높이의 1/6, 최소 2px — det 상자는 글자보다 조금 넓어 띠는 대부분 배경)의 최빈색(채널당 4비트)을 배경으로, 상자 안에서 배경과 RGB 거리 48 넘게 다른 픽셀 중 **가장 높은 대비**. 기준 = 4.5:1을 골랐으면 4.5, 아니면 3.
   - 가장 높은 값: 안티에일리어싱 중간색과, 화면 글꼴에서 회색으로만 그려지는 가는 획(`ㅣ`)이 아니라 획의 진한 색으로 판정하려고.
   - 상자 전체가 아니라 가장자리로 배경을 정하는 이유: 큰 굵은 글자는 상자 안에서 글자색이 더 많을 수 있다. WCAG도 글자와 맞닿은 배경을 본다.
   - 가장자리마저 최빈색이 30% 미만(사진·그라데이션 위 배너 제목)이면 **"배경 복잡"**(회색 상자, 숫자 없음). 1차 구현은 이런 상자를 조용히 건너뛰어 "큰 글씨가 안 잡힌다"는 수동 확인 결과가 나왔다(2026-11-22).
3. **아이콘** (늘 3:1 — WCAG 1.4.11, 토글 없음): 글자 상자와 겹치지 않는 픽셀 덩어리 중 아이콘다운 것만. 그림은 뺀다 (사용자: "아이콘도 잡아야 하는데 그림이 잡힐 필요는 없다"). 한때 [아이콘] 토글을 두었다가 뺐다.
   - 칸(96 DPI 24px)마다 최빈색 배경(30% 미만이면 없음). 그 칸·이웃 8칸 배경 어느 것과도 색이 다른 픽셀만 덩어리 픽셀(칸 경계에 걸친 카드·띠 가장자리 제외). 8방향 연결 덩어리(6픽셀 미만 버림), 대비 = 최댓값.
   - 가까운 덩어리(칸 1/3 이내)를 합친 상자 중: 긴 변 10~64px, 짧은 변 6px 이상(96 DPI 기준, 그림 조각·가는 선 제외), 렌즈 가장자리에 걸려 잘리지 않은 것.
   - **색이 한두 가지**: 배경에서 가장 먼 쪽 픽셀의 최빈색(+ 꽤 다른 둘째 색이 15% 넘으면 그것도)을 아이콘색으로 보고, 덩어리 픽셀의 85% 이상이 "배경↔아이콘색" 선분에서 RGB 40 이내여야 한다(안티에일리어싱 중간색은 선분 위). 여러 색이 섞인 일러스트·사진 조각은 그림.
   - 알려진 한계: OCR이 아이콘을 글자로 보면(전화기·화살표) 글자 기준으로 판정된다. 작은 단색 그림 조각은 아이콘으로 잡힐 수 있다.

### 4.3 렌즈 창 (`lens.rs`)

- `WS_POPUP`, `WS_EX_TOPMOST | WS_EX_LAYERED | WS_EX_TOOLWINDOW`, `UpdateLayeredWindow`(픽셀 알파). 안쪽은 알파 0 → 클릭 통과.
- **검사 시점**: 띄울 때 · 손잡이 [검사] · `Enter`/`F5` · 옮기기·크기 조절을 끝냈을 때 (끝낸 뒤 자동 검사는 설계자 판단: 한 번의 동작이라 실시간이 아니고, 옮길 때마다 [검사]를 누르는 수고를 던다).
  검사 = 캡처 → det → 분석 → 그리기, 0.1초 남짓 (그 사이 지난 상자를 지운다).
- 0.5초 타이머는 검사하지 않고 캡처만 비교한다: 검사한 뒤 아래 화면이 바뀌면(스크롤 등) 상자를 지운다.
- 손잡이(위 띠): 왼쪽 토글 [✓ 4.5:1] [✓ 3:1], 오른쪽 [검사] [닫기]. 요약 글·상태 글은 없다 (사용자 결정, 2026-11-22). 나머지는 끌어 이동, 테두리로 크기 조절, `Esc` 닫기.
  - 토글: 켜짐 = 흰 네모 안 강조색 체크(선으로 그림) + 흰 글, 꺼짐 = 빈 네모 + 흐린 글(흰색 55% + 강조색). 누르면 바로 다시 검사. 마지막 하나는 끌 수 없다.
- 색: 테두리·손잡이 접근성 강조색 `#15803d`(색맹 안경과 같음), 미달 상자 `--destructive` `#c42b1c`(선 2px), 통과 상자 `--success` `#107c10`(선 1px), 배경 복잡 상자 `--muted-foreground` `#6b6b6b`(선 1px, 글 "배경 복잡"), 상자 글 바탕은 상자 색, 글 흰색. 배경 복잡 → 통과 → 미달 순으로 위에 그린다. 상자 글은 상자 위(자리 없으면 안쪽 위).

## 5. 앱 공용 부품: 실행 버튼 작업대

- 버튼(enum 값)이 하나면 2열이 아니라 폭 전체로, 여백을 키워 그린다. (기준 옵션 패널은 한때 붙였다가 기준을 렌즈로 옮기며 되돌렸다)

## 6. 테스트

- 단위(합성 이미지, 글자 상자는 테스트가 준다): 흰 바탕 검정 글자(안티에일리어싱) → 통과 · 회색 가는 획이 있는 줄 → 통과 · `#999` → 미달(≈2.85), 상자 그대로 · `#777`(4.48) → 4.5 기준 미달, 3 기준만이면 통과 · 같은 휘도 빨강/초록 → 미달 · 카드 위 글자는 카드 바탕 기준 · 잡음 위 상자 → 배경 복잡 · 큰 굵은 글자 → 가장자리 배경 기준 · 아이콘 3:1 · 선 아이콘·두 색 아이콘은 아이콘, 여러 색·큰 그림은 아님 · 먼 아이콘 따로 · 큰 면·선·잡음 무시 · 이미지 밖 상자 → 자름 · 대비 공식(흑/백 21).
- 실제 모델(모델 파일이 있을 때): det 상자 → 분석까지.
- 단위: 스키마(옵션은 실행 버튼 하나), 손잡이 토글·[검사]·[닫기]·끌기 판정, 토글은 하나 이상 남김, 최소 크기, 상자 문구.
- 공용: `ai-common` `det_size`(대체텍스트에서 옮김), 대체텍스트 실제 모델 테스트 그대로 통과.
- DLL 일치 테스트.
- 수동: 렌즈가 자기 표시를 다시 분석하지 않음, [검사]·Enter, 스크롤하면 상자 지움, 안쪽 클릭·스크롤 통과, 이동·크기 조절 뒤 검사, 업데이트·제거 중 렌즈, 125%·150% 배율.

## 7. 설계자에게 맡긴 것

- 칸 크기·거리·채움 임계값(위 값은 출발점), 상자 글 자리, 손잡이 글꼴, 옮긴 뒤 자동 검사
