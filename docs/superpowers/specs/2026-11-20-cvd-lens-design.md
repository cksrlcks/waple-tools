# 색맹 안경 (`a11y.cvd_lens`) 설계

작성일: 2026-11-20 · 기준 문서: [docs/plan.md](../../plan.md), [2026-11-10-image-first-addon-design.md](2026-11-10-image-first-addon-design.md)

## 1. 왜

디자이너·개발자는 대부분 색각이상이 아니라서, 자기가 만든 화면의 어떤 색 조합이 색각이상인 사람에게 구분되지 않는지 모른다.
**색각이상인 사람이 되어 보고** 화면을 점검하는 도구가 필요하다. 보정(색각이상인 본인이 쓰는 것)이 아니라 시뮬레이션이다.

모양: 버튼을 누르면 테두리만 있는 투명한 위젯이 화면 위에 떠다니고, 위젯 아래 화면이 색각이상인 사람 눈에 보이는 색으로 비친다. 파일을 만들지 않고 보기만 한다.

시험판(저장소 밖, 버린 코드)으로 Windows Magnification API 방식이 동작함을 확인했다.

## 2. 목표 / 비목표 / 실패 조건

**목표**

- 접근성 탭의 **추가 설치 도구(DLL)** "색맹 안경". 설치·업데이트·제거는 다른 추가 도구와 같다.
- 도구 화면에 보기 방식별 버튼 4개(적색맹 · 녹색맹 · 청색맹 · 전색맹) → 누른 방식으로 떠 있는 렌즈 창. 이미 떠 있으면 새로 띄우지 않고 그 방식으로 바꿔 앞으로 가져온다. (사용자 결정: 들어가서 바꾸는 게 귀찮으니 바로 고르는 버튼, 렌즈 안에서 바꾸기도 유지)
- 렌즈: 항상 위, 손잡이로 이동, 가장자리로 크기 조절, 본 앱을 최소화해도 남는다. 다른 앱 위에도 대 볼 수 있다.
- 보기 방식 4가지: 적색맹 · 녹색맹 · 청색맹 · 전색맹(흑백). 렌즈 안에서 바꾼다.

**비목표**

- 보정(daltonize) — 쓸 사람이 생기면 보기 방식을 추가한다
- 정도 조절(약함~심함) — 가장 심한 경우에도 구분되면 약한 경우는 문제없다. Machado 표가 정도별 값을 갖고 있어 나중에 슬라이더로 추가 가능
- 화면 전체 필터 (Windows 설정 → 접근성 → 색 필터가 이미 한다)
- 캡처·저장, 확대 배율, 여러 개의 렌즈 동시 표시

**실패 조건 (동작해도 실패)**

- 화면을 캡처해 CPU로 색을 바꾸는 방식 (무겁고, 자기 창 제외 문제가 생긴다)
- 도구를 열기만 했는데 렌즈가 뜬다 (버튼을 눌렀을 때만)
- 렌즈가 떠 있는 동안 도구를 제거·업데이트하면 앱이 죽는다
- 앱에 이 도구 전용 화면 코드가 들어간다 (앱에는 다른 도구도 쓸 수 있는 공용 부품만)
- 네트워크 사용, 새 크레이트 의존성 추가

## 3. 제약

- Windows 전용 앱이다. 렌즈는 Win32 + Magnification API(`magnification.dll`, OS 기본 포함)로 만든다.
- 의존성: 새 크레이트에 `windows-sys = "0.61.2"`를 직접 추가한다 (잠금 파일에는 다른 크레이트를 거쳐 이미 있어 새로 받지 않음, MIT/Apache-2.0). CLAUDE.md대로 커밋 메시지에 이유·라이선스를 적는다. feature: `Win32_Foundation`, `Win32_Graphics_Gdi`, `Win32_System_LibraryLoader`, `Win32_System_Threading`, `Win32_UI_HiDpi`, `Win32_UI_Input_KeyboardAndMouse`, `Win32_UI_Magnification`, `Win32_UI_WindowsAndMessaging` (필요하면 설계자가 더한다).
- AI 모델 없음 → 카탈로그에 `ai` 없음.
- 원본 파일·`out_dir`을 건드리지 않는다.
- 색 변환은 감마 공간 근사다. Magnification API의 색 행렬(5×5)에는 선형화 단계를 넣을 수 없다. 코드에 `ponytail:` 주석으로 남긴다.

## 4. 방식 (고려한 것)

| 방식 | 장단점 | 결정 |
|------|--------|------|
| Magnification API 렌즈 (배율 1, `MagSetColorEffect`) | OS가 GPU로 그린다. 가볍고, `MagSetWindowFilterList`로 자기 창 제외. 근사 계산 | **채택** |
| 화면 캡처 + 직접 색 변환 | 정확한 선형 계산 가능. 코드 많고 무겁다 | 뺌 |
| 화면 전체 색 효과 (`MagSetFullscreenColorEffect`) | 가장 간단. 떠다니는 위젯이 아니다 | 뺌 |

넣을 곳:

| 방식 | 장단점 | 결정 |
|------|--------|------|
| A. 기본 내장 (`app/src-tauri`) | 수명 관리가 가장 쉽다. 기본 내장이 늘어난다 | 뺌 |
| B. 추가 설치 DLL | 다른 추가 도구와 같다. DLL이 내려갈 때 렌즈 스레드 문제 | **사용자 선택** |

## 5. 설계

### 5.1 카탈로그 · 크레이트

- `catalog/tools.json`: `{ "id": "a11y.cvd_lens", "name": "색맹 안경", "category": "a11y", "description": "색각이상인 사람 눈에 보이는 화면을 떠 있는 렌즈로 봅니다.", "builtin": false }` — 대체텍스트 다음 줄. 이름·설명 문구는 설계자 판단(사용자가 쓴 말 "색맹안경"에서 땀).
- 크레이트 `crates/tools/a11y-cvd-lens/`, `export_tool!` 한 줄로 내보낸다. `ToolKind::Interactive`, 스키마 루트에 `x-input: "none"`.
- 옵션 하나: `mode` (enum `protan` · `deutan` · `tritan` · `achroma`), 5.6의 실행 버튼으로 그린다. 각 값의 라벨과 한 줄 설명(설계자 판단, 무엇이 헷갈리는지):
  - 적색맹 — 빨강이 어둡게, 빨강·초록·갈색이 비슷하게 보임
  - 녹색맹 — 빨강·초록이 누렇게 비슷해짐 (가장 흔함)
  - 청색맹 — 파랑·초록, 노랑·분홍이 헷갈림
  - 전색맹 — 색 없이 밝기만 보임
- 렌즈 안에서도 바꿀 수 있다 (다른 앱을 보는 중에 앱으로 돌아오지 않아도 되게). 렌즈 안에서 바꾼 것은 앱 쪽에 알리지 않는다.

### 5.2 `run()` 동작

- 렌즈가 없으면 새 스레드를 만들어 렌즈 창과 메시지 루프를 돌리고 바로 돌아온다.
- 렌즈가 있으면 `opts.mode`로 바꾸고 앞으로 가져오고(`PostMessage`로 렌즈 스레드에 요청, 보기 방식 번호를 함께) 바로 돌아온다. 새로 띄울 때도 `opts.mode`로 시작한다.
- 렌즈가 있는지는 5.3.1의 창 찾기로 판단한다 (DLL `static`만으로는 업데이트 뒤 두 DLL이 서로를 모른다).
- 돌려주는 블록: 짧은 안내 글 하나 (예: "렌즈를 띄웠습니다. 손잡이를 끌어 옮기고 Esc로 닫습니다."). 블록 종류는 기존 `Text` 계열 중 알맞은 것.

### 5.3 DLL 수명 (제거·업데이트 안전)

- 렌즈 스레드가 **열려 있는 동안만** DLL 참조를 하나 더 쥔다: 렌즈를 띄울 때 `GetModuleHandleExW(GET_MODULE_HANDLE_EX_FLAG_FROM_ADDRESS, …)`(PIN 없이, 참조 수 +1), 렌즈 스레드가 끝날 때 `FreeLibraryAndExitThread`로 놓는다. 그래서 렌즈 스레드는 `std::thread`가 아니라 `CreateThread`로 만든다 (Rust 스레드 정리를 건너뛰고 끝나므로).
- 그 사이 `AddonTool`이 해제돼도(제거·업데이트) DLL 코드는 렌즈가 닫힐 때까지 남는다. 닫히면 평소처럼 내려간다.
- PIN(프로세스 끝까지 고정)은 쓰지 않는다: 렌즈를 한 번 띄운 뒤 "제거 → 같은 버전 다시 설치"가 앱을 다시 시작할 때까지 실패하기 때문 (`store.rs` `write_version`이 같은 경로의 `tool.dll`로 이름을 바꾸는데, 올라가 있는 DLL은 바꿀 수 없다).
- 남는 제한 (설계자 판단으로 허용): **렌즈가 떠 있는 동안** 제거 → 같은 버전 다시 설치는 렌즈를 닫을 때까지 기존 오류("도구 파일을 저장할 수 없습니다.")가 난다. 업데이트는 새 버전 폴더라 상관없다.
- 앱은 이미 "열린 DLL 파일은 다음 시작 때 지운다"(`app/src-tauri/src/addons/mod.rs` `uninstall`, `cleanup`). 앱 쪽 설치 모듈은 고치지 않는다.
- 제거 후에도 열린 렌즈는 닫을 때까지 동작한다. 허용.
- 참조 없이 DLL이 내려가면 렌즈 스레드가 해제된 코드를 실행해 앱이 죽는다 — 테스트로는 못 잡으니 수동 확인 항목에 넣는다.

### 5.3.1 렌즈는 프로세스에 하나

- 업데이트 뒤에는 예전 DLL(렌즈를 띄운 쪽)과 새 DLL이 함께 올라가 있고 `static`을 나누지 않는다. 그래서 "렌즈가 이미 있나"는 DLL `static`이 아니라 **창으로** 판단한다: 고정 창 클래스 이름(예: `WapleCvdLens`)으로 `FindWindowExW`를 돌며 같은 프로세스(`GetWindowThreadProcessId`)의 창을 찾는다. 있으면 그 창에 앞으로 오기를 요청하고, 없으면 새로 띄운다 (설계자 판단).
- 렌즈가 항상 하나라 `MagInitialize`/`MagUninitialize`도 한 스레드만 부른다.

### 5.4 렌즈 창

- 호스트 창: `WS_POPUP | WS_THICKFRAME | WS_CLIPCHILDREN`, `WS_EX_TOPMOST | WS_EX_LAYERED | WS_EX_TOOLWINDOW`(작업 표시줄에 안 나옴), 알파 255.
- 자식: `WC_MAGNIFIER` 창. 배율 1(`MagSetWindowTransform` 단위 행렬), `MagSetWindowFilterList(EXCLUDE, 호스트)`.
- 약 16ms 타이머로 `MagSetWindowSource(자식 창의 화면 좌표)` + 다시 그리기.
- 손잡이(위쪽 띠): `WM_NCHITTEST`에서 `HTCAPTION`. 보기 방식 이름을 누르면 네 가지 메뉴(`TrackPopupMenu`), 오른쪽에 [닫기] 글자 버튼(상단 X 아이콘 금지 규칙). 키보드: `1`~`4` 보기 방식, `Esc` 닫기.
- 테두리·손잡이: 단색. docs/UI-SYSTEM.md의 **접근성 탭 강조색(라이트 값)** 을 Win32 색 상수 하나로 옮겨 쓴다 (화면 코드가 아니라 네이티브 창이라. 설계자 판단).
- 처음 위치·크기: 본 앱 창 근처 또는 주 모니터 가운데, 520×360 정도. 기억하지 않는다.
- DPI: 앱 프로세스(Tauri)가 이미 모니터별 DPI 인식이다. DLL은 프로세스 설정을 바꾸지 않고, 필요하면 렌즈 스레드에서 `SetThreadDpiAwarenessContext`만 쓴다.
- `MagInitialize`는 렌즈 스레드 시작 때, `MagUninitialize`는 렌즈를 닫을 때.

### 5.5 색 행렬

Machado 2009, 심각도 1.0 (out = M · in). `MAGCOLOREFFECT`는 행 = 입력, 열 = 출력이라 전치해서 넣는다.

- 적색맹: `[[0.152286, 1.052583, -0.204868], [0.114503, 0.786281, 0.099216], [-0.003882, -0.048116, 1.051998]]`
- 녹색맹: `[[0.367322, 0.860646, -0.227968], [0.280085, 0.672501, 0.047413], [-0.011820, 0.042940, 0.968881]]`
- 청색맹: `[[1.255528, -0.076749, -0.178779], [-0.078411, 0.930809, 0.147602], [0.004733, 0.691367, 0.303900]]`
- 전색맹: 세 행 모두 `[0.299, 0.587, 0.114]`

보기 방식은 버튼으로 고른다. 렌즈 안 메뉴·`1`~`4`도 같은 순서.

### 5.6 앱 공용 부품: 실행 버튼

지금 `x-input: "none"` 도구는 열자마자 실행된다. 이 도구는 버튼을 눌렀을 때만 실행해야 한다.

- enum 옵션 필드에 확장 `x-run-buttons: true`를 추가한다. 이 필드는 라디오 대신 **값마다 버튼 하나**로 그린다 (버튼 글 = 값의 라벨, 아래 작은 글 = 값의 설명). 버튼을 누르면 그 값을 넣은 옵션으로 `run_interactive`를 한 번 부르고 돌아온 블록을 보여 준다.
- 스키마에 `x-run-buttons` 필드가 있는 도구는 자동 실행(열 때, 옵션 바꿀 때)을 하지 않는다.
- 다른 도구도 쓸 수 있는 일반 기능이다. 키 이름·enum 라벨/설명을 스키마에 싣는 방식은 기존 `x-` 키와 enum 처리(`schemaToFields`)를 따르고, 맞지 않으면 설계자가 고른다.
- 버튼 모양·자리는 docs/UI-SYSTEM.md를 따른다.

```
색맹 안경
[ 적색맹 ]  빨강이 어둡게, 빨강·초록·갈색이 비슷하게 보임
[ 녹색맹 ]  빨강·초록이 누렇게 비슷해짐 (가장 흔함)
[ 청색맹 ]  파랑·초록, 노랑·분홍이 헷갈림
[ 전색맹 ]  색 없이 밝기만 보임
```

## 6. 테스트

- 단위: 전치 함수 — 전색맹 행렬의 입력 R 행이 `[0.299, 0.299, 0.299, 0, 0]`인지, 알파·오프셋 칸(`t[18]`, `t[24]`)이 1인지.
- 단위: 메타·스키마 — 카탈로그 id와 일치, `x-input: "none"`, `mode`에 `x-run-buttons`, enum 값 4개.
- 단위: `mode` 문자열 → 보기 방식 번호 (모르는 값은 녹색맹).
- 렌즈 창 자체는 자동 테스트하지 않는다 (화면 필요). 수동 확인:
  1. 도구를 열기만 하면 렌즈가 뜨지 않는다
  2. [적색맹] → 적색맹으로 뜸, 이어서 [청색맹] → 렌즈는 하나 그대로, 청색맹으로 바뀌고 앞으로 온다
  3. 이동·크기 조절·보기 방식 메뉴·`1`~`4`·`Esc`·[닫기]
  4. 렌즈가 렌즈 자신을 비추지 않는다 (무한 거울 없음)
  5. 렌즈가 떠 있는 상태에서 도구 제거 → 앱이 죽지 않고, 렌즈는 닫을 때까지 동작
  6. 렌즈가 떠 있는 상태에서 도구 업데이트 → 앱이 죽지 않고, 보기 방식 버튼을 누르면 새 렌즈 없이 기존 렌즈가 바뀌어 앞으로 온다
  6-1. 렌즈를 닫은 뒤 제거 → 같은 버전 다시 설치가 된다
  7. 125%·150% 배율 모니터에서 렌즈 안 화면이 렌즈 바로 아래와 맞는다

## 7. 설계자에게 맡긴 것

- 안내 글 블록 종류, 렌즈 처음 위치, 손잡이 높이·글꼴
- 렌즈 스레드와 `static` 상태 구조
- `x-run-buttons` 처리의 프론트 코드 구조 (기존 `x-` 키 처리 방식을 따른다)
